Authentication decision

认证结论：短期会话 + 长期客户端身份

descriptor 权限和 session token 是必要底层，但不能单独识别同一用户下的调用进程。最终模型必须让已配对 CLI 证明它持有独有私钥。

第一层

启动期 Session Secret

  • 每个 Thunderbird 实例启动时生成 256-bit secret。
  • descriptor 目录 0700、文件 0600，原子写入。
  • 负责实例发现、阻挡网页与其他 OS 用户、约束短期会话。
  • 启动、重载、撤销时轮换；不建议 MVP 做高频周期轮换。
+
第二层

Ed25519 客户端身份

  • 首次配对由 CLI 生成密钥对，私钥优先存 macOS Keychain。
  • 扩展仅保存公钥、client ID、授权账号与能力。
  • 每请求签名 protocol、instance、method、path、body hash、timestamp、nonce、request ID。
  • 扩权必须 Thunderbird UI 批准，撤销立即使会话与确认失效。
token-only 的边界：任何能以同一 OS 用户读取 descriptor 的进程都可复制 session token。timestamp 与 nonce 只能阻止旧请求重放，不能证明调用者是已配对 CLI；X-Thunderbird-Client 也只是可伪造字符串。若 Ed25519/Keychain 技术验证失败，最多允许 token-only 的只读 MVP，禁止写入与外发。
Exit criteria

Phase 1 必须通过的技术验证与退出门

每项都需要可重复的机器证据；“设计上应该可行”不算通过。

  1. 扩展兼容：在 Thunderbird 128 ESR 与当前目标版本稳定启动/停止最小 XPI，确认 MV3/Experiment 生命周期和签名发布约束。
  2. Server 安全：只绑定 127.0.0.1；错误 Host、Origin、method、Content-Type、超限 body 和浏览器 fetch 全部拒绝。
  3. 密钥能力：验证 Ed25519 生成/签名/验证与 Keychain 存取；无 UI、SSH 和 CI 环境行为明确，性能满足请求路径。
  4. 同用户威胁：恶意进程即使读取 session secret，没有私钥也不能调用业务 route；复制、改 body/path、跨实例/跨 client 均失败。
  5. 配对抗攻击：六位码仅做人眼比对；256-bit intent secret、5 分钟过期、UI 批准、穷举/重放/批准竞态测试通过。
  6. 发现与多实例：owner、权限、symlink、原子更新、stale PID、Terminal/GUI/双 profile 和歧义失败均通过。
  7. 撤销与版本：撤销后现有连接、undo、confirmation 立即失效；协议主版本不兼容时失败关闭。
  8. 隔离 E2E：使用 fixture profile，不接触个人邮箱；失败后无 token、临时正文、监听进程或 descriptor 残留。

退出门 P0 阻塞全部解除、身份模型冻结、以上负向测试通过，且 Phase 1 仍然没有邮件写入或发送 endpoint，才进入只读 MVP。

Real send E2E gate

何时才允许向用户授权地址进行真实发送 E2E

不是 Phase 1，也不是只读 MVP。必须先在本地捕获 SMTP / 隔离测试域证明 exactly-once 语义，然后满足全部条件并获得用户对具体地址、内容和时点的单次明确授权。

技术前置

  • 只读、可逆、附件、草稿阶段全部通过
  • revision 能检测收件人/正文/附件变化
  • 未知网络结果通过 operation status 处理，不重复发送
  • 外发威胁模型和独立安全审查通过

环境前置

  • 先通过本地 SMTP sink E2E
  • 使用专用测试 identity 和最小授权账号
  • 外发能力默认关闭，由 Thunderbird UI 单独启用
  • 日志、临时文件和撤销/撤权行为验证完毕

用户授权前置

  • 用户明确指定授权收件地址
  • 展示 From、To/Cc/Bcc、主题、正文摘要和附件
  • 确认绑定最新 draft revision 且一次性、短期有效
  • 不把一般“继续”当成未展示内容的发送授权

当前状态：不满足以上条件，因此禁止真实发送 E2E，也不得读写用户邮件。
