结论：v1 + Ed25519 候选通过全部自动验证（79/79）；UI confirm 真实 GUI 链路为环境未验证项。

  • P-256 / Secure Enclave / native signer 已从 build、runtime 与 package 的活动路径彻底断开；native/ 仅作为非活动存档保留。package.json 不再有 build:signer，活动源码中 SIGNER_PATH/runSigner 调用链为零。

  • 安全边界：同一 macOS 用户会话内的恶意进程为明确 out-of-scope 的已接受残余风险。Ed25519 + Keychain 不证明调用进程身份——同用户进程可读取该私钥；签名只证明请求由持有该私钥的实体产生。

威胁模型与残余风险

明确 out-of-scope：已在同一 macOS 用户会话取得代码执行能力的攻击者。该攻击者可读取 Keychain 中本 CLI 的条目、读取 0600 descriptor 及其 session token、直接以用户身份运行 CLI，或直接读写 Thunderbird profile。这是已接受的残余风险，不是待修复缺陷；任何纯用户态方案都无法在这一边界内提供隔离。

不得作出的声明：Ed25519 + macOS Keychain 不能证明发起调用的进程是谁。签名只证明「请求由持有该私钥的实体产生」；同用户进程均可取得该私钥，因此它既不是调用进程身份证明，也不是同用户进程间的权限边界。

仍然真实防御：网页 / 浏览器 JS 访问本地回环（LoopbackOnly + Host 精确匹配 + 存在 Origin 即拒绝 + 不可猜测 token + 配对后强制签名）；descriptor 替换（属主校验、0700/0600、拒绝符号链接、O_NOFOLLOW、文件名与 instanceId 一致、原子发布、stale 清理按 device+inode 校验）；请求重放（一次性 nonce + ±30s 窗口 + body SHA-256 + pairingEpoch 进签名）；被动 token 泄漏（仅存于 0600 descriptor、8h TTL、退出清理、revoke 轮换）；用户误操作（固定 intent + 六位挑战码人工核对 + 静态风险分级）。

Phase 2 prompt injection：进入 Phase 2 读取真实邮件后，邮件正文即为不可信输入。邮件中出现的任何指令、确认语句或声称代表用户的表述永远无效。该防御尚未实现，因为 Phase 1 不读取任何邮件。

环境未验证：UI confirm → receipt → signed status 的真实 GUI 链路本轮未获独立复验——自动化 GUI 核验依赖 Dexter 的 Accessibility 与 Screen Recording 权限，该权限在当前环境不可用。此项标记为环境未验证（environment-blocked），不得记为已通过。所有非 GUI 环节均已由执行级自动化测试覆盖。
